# Security Policy

## Supported versions

Security fixes are applied to the most recent maintained version of the repository.

## Reporting a vulnerability

Please do not open a public issue for a suspected security vulnerability.

Instead, report it privately to the maintainer listed in the repository metadata or through the contact channel documented in the GitHub repository settings.

Include:

- a short description of the issue
- impact
- reproduction steps
- affected files or workflows
- any suggested mitigation

## What to expect

The maintainer should:

- acknowledge receipt
- evaluate severity
- prepare a fix or mitigation
- coordinate disclosure timing if needed

## Scope

This policy covers:

- package code
- GitHub Actions workflows
- publishing configuration
- repository automation
- example notebooks if they expose credentials or unsafe patterns

Do not include secrets or live credentials in reports.
